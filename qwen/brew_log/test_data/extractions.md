# 抽出記録のデータ例

## test fixture（5件・実値）

[`test/helpers/harness.dart`](../test/helpers/harness.dart) の `extractionA()` は全件 **15 g / 240 ml / 90℃**、味覚は**酸味0.70 / 苦味0.30 / 甘み0.60** 固定、注湯ログは2点（蒸らし 0秒・1投目 55秒）なので**所要は全件55秒**になります。

| id | 日時 | 数日前 | 豆名 | 豆id | 評価 | メモ |
|---|---|---|---|---|---|---|
| `ex-1` | 2026-10-30 09:00 | 0日 | エチオピア ゲイシャ | `bean-a` | ★5 | 香りが立っている |
| `ex-2` | 2026-10-29 09:00 | 1日 | エチオピア ゲイシャ | `bean-a` | ★4 | — |
| `ex-3` | 2026-10-27 09:00 | 3日 | グアテマラ アンティグア | `bean-b` | ★3 | — |
| `ex-4` | 2026-10-21 09:00 | 9日 | グアテマラ アンティグア | `bean-b` | ★5 | — |
| `ex-5` | 2026-09-29 09:00 | **31日** | エチオピア ゲイシャ | `bean-a` | ★2 | — |

`ex-5` だけ30日窓（2026-10-01 以降）の外に置くのが狙いで、集計の境界テストに使えます（窓内4件・平均4.25／全期間5件・平均3.8）。

## demo（21件・ループ生成）

[`lib/demo/demo_data.dart`](../lib/demo/demo_data.dart) の `demoExtractions()` は、撮った日基準で相対的に生成します。1行ずつ固定値を書くとおくれた日が古びてしまうため、**式**で持たせています。

| 項目 | 式（`i` = 0〜20） |
|---|---|
| id | `demo-ex-{i}` |
| 日時 | 本日00:00 − `daysAgo`日 + `7+(i mod 10)`時 + `5+13*(i mod 4)`分 |
| daysAgo | `i < 7 ? i : 2*i − 5` |
| 豆 | `demoBeans[i mod 3]` … 0:ゲイシャG1(浅) / 1:グアテマラ(中) / 2:ブラジル(深) |
| レシピ | `demoRecipes[i mod 2]` … 偶数: 01 朝の一杯 / 奇数: 02 ゆっくり4投 |
| 豆量・湯量・湯温 | 対応レシピのまま（15g/240ml/92℃ または 18g/300ml/88℃） |
| 味覚 | 酸味 `0.25+0.06*(i mod 9)` ／ 苦味 `0.70−0.05*(i mod 11)` ／ 甘み `0.35+0.05*(i mod 10)`（0..1 に clamp） |
| 注湯ログ | そのレシピの `BrewPlan` のステップ数（4点 or 5点）、`elapsedMs` は各ステップの開始位置 |
| メモ | 偶数のときだけ `notes[i mod 5]`、奇数は空 |

`notes` の中身:

1. 香りが立っていて良い。細挽きすぎたかも
2. 温度を2℃下げたら甘みが出た
3. 蒸らしが短く、薄い味わいになった
4. 雑味あり。注湯が荒かった
5. 今回いちばん良い当たり

### この式から決まる集計値（スクショの検算に使える）

| 値 | 内訳 |
|---|---|
| 総件数 21杯 | 評価の合計 78 → 平均 **3.7** |
| 直近30日 18杯 | `daysAgo ≤ 29` の i=0..17。合計 66 → 平均 **3.67** |
| 豆ごとの件数 | 7 / 7 / 7 |
| 豆ごとの平均 | ブラジル 4.0 > グアテマラ 3.9 > ゲイシャ 3.3 |

→ `screenshots/stats_*.png` の「直近30日の抽出 18杯」「平均 3.7」「豆ごとの平均評価」の順序と一致します。
