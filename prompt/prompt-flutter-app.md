## アプリ概要
**Brew Log — ハンドドリップ珈琲の抽出タイマー＆記録アプリ**

- 豆を登録し、抽出レシピに沿ってタイマーで淹れ、結果を記録・振り返るアプリ
- 通信は一切なし。データはすべて端末ローカルに保存する
- UI 言語は日本語

## 機能要件
1. **豆の管理**
   - 豆の一覧／登録／編集／削除（名前、産地、焙煎度［浅・中・深］、焙煎日、メモ）
   - 焙煎日からの経過日数を表示する
2. **抽出タイマー**
   - レシピ（豆の量 g、湯量 ml、湯温 ℃、蒸らし時間、注湯回数）を設定してスタート
   - 「蒸らし → 1投目 → 2投目 …」のステップごとに、残り時間と目標の累計湯量を大きく表示
   - 一時停止・再開・リセットができる。ステップが切り替わるときにハプティクスで知らせる
   - 実行中は画面がスリープしないようにする
3. **抽出記録**
   - タイマー終了後に評価（★1〜5）と味のメモ（酸味・苦味・甘みのスライダー、自由記述）を保存
   - 履歴一覧と詳細表示。豆で絞り込める
4. **振り返り**
   - 直近30日の抽出回数と平均評価を表示
   - 豆ごとの平均評価ランキング
   - グラフは外部パッケージを使わず、CustomPaint などで自作してよい
5. **設定**
   - テーマ切替（ライト／ダーク／システム）
   - 全データの削除（確認ダイアログ付き）

## デザイン要件（重視します）
- **Material 3** をベースに、「標準のサンプルアプリっぽさ」を消して洗練された印象にする
  - 珈琲を連想させる落ち着いたトーンのカラースキーム（seed color の選定理由を README に書く）
  - タイポグラフィの階層（displayLarge〜labelSmall）を意図して使い分ける。タイマーの数字は等幅で大きく
  - 余白・角丸・elevation のルールを ThemeData と定数にまとめ、画面ごとに場当たり的な値を書かない
- ライト／ダークの両方で破綻しないこと（コントラストにも配慮）
- 空状態（データ0件）の画面を用意し、次に何をすればいいかが分かるようにする
- 画面遷移やリスト追加・削除に、控えめなアニメーションを入れる
- フォントは**アプリに同梱**するか、システムフォントを使う（`google_fonts` の実行時ダウンロードは不可）
- スマホ縦画面を前提にしつつ、小さい画面（幅 360dp）でも崩れないこと

## 技術要件
- Flutter stable の最新版を使う。最初に `flutter --version` で確認し、結果を README に記載する
- 状態管理と永続化のパッケージは自由に選んでよいが、選んだ理由を README に書く。依存パッケージは必要最小限にする
- 画面・状態・データ層を分離した、読みやすいフォルダ構成にする
- 保存データの読み込みに失敗したり壊れていたりしてもクラッシュせず、ユーザーに分かる形で知らせる
- `flutter analyze` を警告0で通す
- ロジック（タイマーのステップ計算、集計）に unit test、主要画面に widget test を書き、`flutter test` を通す
- iOS シミュレータまたは Android エミュレータで起動し、主要な画面のスクリーンショットを `brew_log/screenshots/` に保存する（ライト／ダーク各1枚以上）
